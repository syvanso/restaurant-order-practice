【階段一：需求釐清與架構設計（/grill-me 訪談）】
--------------------------------------------------------------------------------

Q1：使用者初衷與主要需求
使用者希望製作一個市面上常見的手機掃碼點餐網頁，主要供練習使用：
點開網頁 ➔ 瀏覽餐點 ➔ 點餐進購物車 ➔ 送出點菜單 ➔ 回看點餐紀錄。
重點需求：
1. 適合手機介面大小（Mobile-First）。
2. 開著網頁時保留該次點餐與歷史加點紀錄，但「離開網頁後」不保存任何資料或個人資訊。
3. 參考市面點餐系統（inline、快一點 QuickClick）的介面與 GitHub 開源事件過濾（eventFilter）、動畫邏輯。
4. 在撰寫代碼前，先釐清想法，暫勿直接寫程式。

Q2：訪談決策點與結果
1. 技術棧選型：
   - 決策：選擇「純前端原生 HTML5 + Modern CSS + JavaScript」。
   - 原因：零建置打包成本、無任何相依套件，任何人雙擊即可離線測試，最適合掛在 GitHub Pages 供手機掃碼練習。
2. 資料生命週期：
   - 決策：採用「sessionStorage」儲存機制。
   - 原因：手機用戶若誤觸「下拉重新整理」或按 F5，資料不會意外遺失；一旦「關閉分頁或關閉瀏覽器」，瀏覽器會徹底銷毀所有紀錄，手機不殘留任何垃圾資料。並提供「🔄 一鍵重置 / 開新桌」按鈕。
3. 餐點規格客製化：
   - 決策：完整餐點規格彈窗（支援麵包基底、蛋熟度、冷熱甜度冰塊、加料加價複選、單品備註）。
4. 歷史點餐紀錄與加點流程：
   - 決策：支援多次「分批加點」紀錄。首次送單產生「第 1 次送單（時間）」與「廚房製作中」狀態；可隨時返回菜單「繼續加點」，送出後產生「第 2 次加點」，自動累計整桌消費總額。
5. 菜單主題選定：
   - 決策：「文青早午餐 / 咖啡輕食館（Breeze & Bite 晨光咖啡）」，包含手打漢堡、早午餐盤、溫沙拉與特調咖啡。

【階段三：GitHub 託管與 GitHub Pages 上線部署】
--------------------------------------------------------------------------------

Q1：如何掛上網路給其他人手機掃碼練習？
- 使用者選擇「GitHub Pages」方案。

Q2：掛在網路上後，是否有辦法隨時關閉/下線？
- 答案：可以！主控權在使用者手中，有 3 種方式：
  1. 一鍵下架（Unpublish Site）：在 Settings > Pages 點選「Unpublish site」，網址立刻失效變 404，程式碼仍保留在倉庫中。
  2. 轉為私有倉庫（Private）：在 Settings 底部改為 Private，免費版私有倉庫不支援 Pages，網頁立刻下線。
  3. 刪除倉庫（Delete Repository）：徹底清除專案。

Q3：推送與部署流程：
1. 本地初始化 Git 倉庫並進行首次 Commit。
2. 使用者建立 GitHub 倉庫：https://github.com/syvanso/restaurant-order-practice.git
3. 透過 GitHub API/MCP 系統將全部檔案（index.html, style.css, menuData.js, app.js, README.md）直接推送到 main 分支。
4. 在 GitHub 倉庫開啟 Pages（Source: Deploy from a branch, Branch: main /root）。
5. 產生公開網址：
   👉 https://syvanso.github.io/restaurant-order-practice/
6. 線上 QR Code 圖片直接產生：
   👉 https://api.qrserver.com/v1/create-qr-code/?size=350x350&data=https://syvanso.github.io/restaurant-order-practice/

【階段四：網址隱私與自訂化說明】
--------------------------------------------------------------------------------

Q1：網址中的用戶名（syvanso）有辦法隱藏或消去嗎？
- GitHub Pages 預設規則固定帶有帳號名。若要隱藏，提供 4 種解法：
  1. 免費短網址（reurl.cc 或 TinyURL）：10 秒搞定，產生的短網址與 QR Code 完全看不到 GitHub 用戶名。
  2. 改用 Vercel 或 Netlify 託管：完全免費，網址可自訂為 https://breeze-cafe-order.vercel.app，完全無個人帳號。
  3. 在 GitHub 建立「組織（Organization）」：如建立名為 breeze-cafe-lab 的組織，網址變成 https://breeze-cafe-lab.github.io/restaurant-order-practice/。
  4. 綁定自訂獨立網域（Custom Domain）。

Q2：平常如果要修改網頁，需要重複上述繁瑣流程嗎？
- 答案：完全不需要！
  - 之前的設定只是一次性初始化。
  - 平常只要儲存檔案，叫助理一鍵同步或在 VS Code 按 Commit & Push，GitHub 在 20 秒內會自動更新線上網頁。
  - 網址與 QR Code 永久固定，不需重新產生。

【階段五：動態效果與互動細節除錯修復（/grill-me）】
--------------------------------------------------------------------------------

使用者回饋問題：
1. 菜單上方分類標籤（🔥 人氣主打、🍳 晨光早午餐等）點擊後無法直接跳到該畫面。
2. 按下加入購物車時，沒有出現拋物線飛入動畫特效。

問題診斷與修復：
1. 分類標籤點擊修復：
   - 原因：handleAppClick 事件過濾器開頭做了 if (!actionEl) return;，而分類標籤 .cat-chip 未帶 data-action，點擊事件在第一行被直接擋掉。
   - 修復：將分類標籤點擊提取到最優先判斷，並改用精確位移計算：
     DOM.menuScrollContainer.scrollTo({ top: scrollOffset, behavior: 'smooth' });
     點擊標籤立即平滑捲動至該分類！

2. 拋物線飛入動畫修復：
   - 原因：加入第一項餐點時，底部懸浮購物車條未具備 .visible 類別（位置處於螢幕底部的 translateY(120%) 之外），導致飛入目標坐標落在螢幕外；且原生 CSS transition 在瀏覽器合併 DOM 樣式時偶爾漏幀。
   - 修復：
     a. 改用物理數學拋物線 requestAnimationFrame，飛行時間 520ms（使用者選擇的經典優雅弧度）。
     b. 小球向上空拱起高飛 120px 弧度，精確優雅落入底部購物車。
     c. 小球視覺增強為 34px 發光立體琥珀橘色圓球（帶白邊與光暈立體陰影）。
     d. 加入餐點時，底部購物車條在動畫啟動瞬間立刻升起迎接小球，落地瞬間觸發購物車徽章果凍彈跳（Jelly Bounce）！
